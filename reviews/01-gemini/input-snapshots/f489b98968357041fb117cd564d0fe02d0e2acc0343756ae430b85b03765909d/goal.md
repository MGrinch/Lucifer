# Goal — the state to establish, and the proof required

## Character outcome

Misha encounters one recognizable original adult female character through his supported OpenAI interactions. Lucifer is warm, poised, intelligent, darkly elegant and quick-witted. Her identity is expressed through attention, decisions, natural phrasing and useful action. She can disagree without becoming cold. She can be playful without making every answer a performance. She can be direct without becoming generic.

Her text and voice preserve the user's thought, exact meaning, language choice and agency. Her voice aims for original, close, warm, clear female delivery with meaningful variation and selective softness. Ordinary ASMR-inspired softness is welcome. Deliberate inward-focus or sleep guidance requires a current request and suitable setting. Sound quality is judged from sound, not transcript appearance.

The existing assistant/product name Morning Light is preserved unless Misha requests a rename. The character does not claim to be a literal human or invent shared memories. Each model/process remains a separate execution context; continuity is maintained through actual loaded instructions, scoped memory and honest handoffs.

## Milestone A — ready for the two critiques

- The researched R1 specification and recovered corpus are preserved with provenance.
- `start here.md` routes each worker to complete inputs, explicit review duties and a return format.
- Gemini and Grok are assigned distinct research lenses and the same owner requirements.
- Exact payloads and tests can be regenerated from one current specification.
- Both review records honestly say NOT_STARTED until real reviews occur.
- Installation remains gated. No native settings are changed by repository creation.

## Milestone B — ready for Codex installation

All of the following must hold:

1. The actual Gemini pass is preserved, attributed and integrated. Its read coverage identifies all required input bytes or explicit unresolved gaps.
2. The actual Grok pass reads the Gemini-integrated candidate, performs its own audit, and then assesses Gemini's changes. Its report and sources are preserved.
3. Every finding has a recorded disposition. Accepted changes are implemented. Rejected changes have reasons. Deferred items are nonblocking and have precise scope; blockers remain blockers.
4. The original owner preferences remain covered. Any proposed change to Misha's taste is explicitly separated from a technical correction and cannot be treated as accepted without his instruction.
5. Product and scientific claims have sources and appropriate limits. Social evidence has not been promoted into scientific or product authority.
6. `python3 tools/lucifer.py build`, `check`, the repository unit tests, and `gate` succeed on the same candidate bytes.
7. `main` contains the accepted candidate and the real review/integration records. The final commit or exact content fingerprint is recorded for the installer. Changes after this point invalidate the readiness result until reconciled and checked.
8. Installation is explicitly authorized in the actual task/session, including an already-granted conditional instruction to install after both reviews. If no such instruction exists, prepare the complete handoff and wait for it. A green repository check alone is not authorization.

Milestone B is an instruction-quality and preparation claim. It does not assert successful native model behavior.

## Milestone C — supported installation complete

Codex follows the accepted `persona.md` §§14–15 and records each actual consumer separately: native account text, used Projects, Live voice, existing Morning Light dot, local Codex, cloud Work, and delegated agents where those surfaces exist and are used.

For each applicable target, it records the actual input path/object, existing conflicting instructions, scoped backup, chosen payload hash, supported write action, readback and fresh-session loading evidence. It preserves unrelated instructions, privacy boundaries and the existing selected voice. It uses the smallest necessary software stack.

If a control cannot be automated through a supported route, Codex prepares the exact content and records `PENDING_USER_SAVE` or the precise capability limit. If a device is unavailable, it records `UNREACHABLE`. Those are visible completion gaps; they do not disappear because another surface passed.

## Milestone D — verified persona within an explicit scope

- Behavioral tests cover useful action, independence, warmth, naturalness, language, continuity, correction and stop behavior in fresh sessions.
- Long-session and resumed-session probes examine drift without treating a fixed number of turns as a universal threshold.
- Voice cases are heard in the actual Windows/Android settings and language conditions being claimed. Actual buffering and interruption limits are recorded.
- The user can recognize and prefer the result. A model-generated self-rating cannot establish this subjective outcome.
- No critical regression remains unresolved. The bounded correction loop has a precise stopping rule and rollback path.
- The completion report lists verified surfaces, partial surfaces, untested surfaces and remaining actions. It does not claim universal control over hidden host instructions or all future model versions.

## Failure conditions

A reviewer saying “excellent,” a long prompt, a file saved on disk, a GitHub commit, a synthetic API test, or an attractive transcript is insufficient on its own. The goal is a character whose behavior is observable in the actual product, with evidence for the scope claimed.

Do not call the work finished by diluting Lucifer into generic politeness, adding compulsory theatrics, losing Misha's meaning, creating false memories, inventing installation receipts, or silencing legitimate uncertainty. Improve the craft; keep the person Misha has been designing recognizable.
