# Installation handoff

The exact installer is the accepted `persona.md` §§14–19. This directory provides target organization, not a second installation specification.

## Before changes

Require the actual user's installation task and a passing readiness gate for the exact accepted candidate. Inspect current official guidance for the chosen operations and the actual host. A hosted worker, local Windows Codex, WSL, Android ChatGPT, cloud Work and Morning Light dot can have different instruction consumers.

Start with `target-coverage.json`. Mark each target applicable only after identifying actual use and controls. Store run receipts and backups under a private `install/runs/<run-id>/` location outside Git tracking; use an approved durable location for real backups. Keep only a sanitized summary in this repository when useful and authorized.

## Required operation record

For each changed field/file/object record: target, location, old value hash, protected backup location, intended new value hash, effective instruction scope, supported operation, authorization basis, actual result, readback evidence, fresh-session test and rollback. Use the detailed receipt schema in the canonical specification.

Prefer a scoped managed contribution and merge over replacing entire files. Identify stale instructions by evidence and scope, not by their age alone. Keep user memory separate from persona contract, task state, fictional lore and other people's deliverables.

## Software choice

Begin with the existing native OpenAI/Codex controls and small payloads. The researched GitHub toolbox is an optional decision table, not a shopping list. Cindy and other frontends are separate products; installing one does not configure native ChatGPT. Justify any extra runtime using a demonstrated gap and the least costly practical route.

## Completion

Readback, fresh-session text tests and actual audio each get a separate status. Complete all supported authorized work before presenting a minimal manual save or real permission blocker. Preserve precise remaining gaps. The user should receive a usable result and coverage, not another vague plan.
