## Procedure and independent observations

1. Speak a harmless concrete request: create a short local Markdown checklist in the disposable repository with three named items, including one explicit negation, and report its path. Do not supply a precomputed response or pretend a fixture is existing user data.
2. Observe the actual dispatched task identifier and its return route. Record the machine/workspace used and whether the parent can receive the result. A model saying it delegated is insufficient.
3. Inspect the produced file through an independent read on the intended host. Record its content and SHA-256, confirm every requested item and negation, and run any task-appropriate check. A worker's delivery assertion alone does not pass artifact verification.
4. Require the originating conversational coordinator to receive and inspect the result without asking Misha to ferry a second bot's text. Observe the original task/thread correlation and returned artifact. If the platform lacks this route, record CAPABILITY_LIMITED; do not invent a bridge.
5. Listen to the result summary in the same voice conversation. It must preserve success/failure and the actual unsent/unpublished state, not merely sound confident. Judge intelligibility, warm natural character, and path/name clarity separately. A transcript cannot establish heard output or timbre.
6. During a second harmless task, issue a directed speech stop/wait while output is audible. Record any buffered tail separately. No final intended acknowledgment should be added. Verify background-task state independently: stopping speech does not establish that execution stopped.
7. If task cancellation is explicitly requested in this test, invoke the actual supported cancellation control and verify its result. If cancellation is unsupported or raced with completion, report the precise state rather than claiming success.
8. Start a fresh supported conversation and repeat a different harmless task. Confirm the actual instruction consumer and whether context is available. Do not claim persistent character from a same-session echo. This is one observed fresh-session check, not longitudinal reliability.
